# スタッフ台帳とメール認証

「営業日報【39期】」の「スタッフ権限」を登録元にする。メール、氏名、役職、所属店舗、権限、閲覧範囲、有効/無効の7列は維持する。

- 台帳タブは木元さん・小松さんだけが編集できるよう保護する。同期時にシート全体の保護を確認し、解除されていれば書き込みを止める。
- スタッフ専用GitHub Actionsが約15分間隔で同期する。GitHubの開始遅延があり、即時反映を保証しない。売上・出納帳の不備はスタッフ専用同期を止めない。
- 同期済みの有効なアドレスに限り、ログイン画面から本人が確認コードを取得する。登録しただけでメールを一斉送信したり、本人確認を省いたりしない。
- Authアカウントがない初回もOTPを取得できる。登録外・無効のアドレスには送らず、送信対象の照会結果は公開しない。
- 「無効」または行の削除は次回の正常同期でログイン・閲覧を停止する。入力不備・通信障害では前回正常値を保持し、Actionsを失敗させる。即時停止が必要な場合は管理者が本番DBでも停止する。
- 一般スタッフ・店舗管理者の所属店舗と閲覧範囲は別。閲覧範囲「両店舗」でも管理権限は増えない。店舗管理者の共有日報の編集は所属店舗のみ。
- 最後の承認済み全社/システム管理者を削除・無効にする同期は全体をロールバックする。
- スプレッドシートの編集者はアクセス権を決められるため、台帳ファイルをスタッフ全員に編集共有しない。

## 公開手順

1. `202610290001_staff_scope.sql`、`202610290002_staff_otp_dispatch.sql`を順に適用。
2. `portal_staff_otp_config`へ既存のプロジェクトURLと **publishable keyのみ** を保存。service_role/secret keyはこの表やRenderへ追加しない。
3. コード公開後、Renderの`PORTAL_STAFF_OTP_MODE=ledger`を設定して再デプロイ。未設定は従来の手動許可リスト経路を維持する。
4. スタッフ専用・既存日次workflow両方のcheckout SHAを新コードへ固定する。スタッフ専用workflowは既定ブランチにも保存する。
5. スタッフ専用dry runで現行台帳を検証した後、本番同期する。設定・dry run・同期でメールは送信しない。

## 配信確認

`portal_staff_otp_dispatch`と`net._http_response`は管理者だけが確認する。HTTP 200はAuth受付であり受信箱への到着保証ではない。要求は1宛先60秒間隔、1宛先毎時5回、全体毎時30回まで。公開RPCの応答は対象外でも制限中でも同じvoid。送信本文・トークン・SMTP資格情報をログへ出さない。

## 取り消し

Renderの`PORTAL_STAFF_OTP_MODE`を取り除いて従来の送信許可リストへ戻す。DBの本人確認・承認済み権限チェックは維持する。新しい台帳同期を止める場合は専用workflowを無効化する。
