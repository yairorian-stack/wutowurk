# 自己評価シート（第1案）

## 使い方

ホームまたは「売上・日報」の「自己評価シートを作成」ボタン、メニューの「自己評価」から開く。Next.js版は `/self-evaluation`、公開確認用サイトは `#/self-evaluation`。

1. 調理部門・接客部門・部門リーダーを切り替える。各部門4分類×5項目、合計20項目。調理部門は依頼者指定の項目を採用し、接客・リーダーは作成を承認された第1案として明記する。
2. 氏名、勤務店舗、評価対象期間を記入する。氏名・期間は任意で、未記入のままシートを作成・印刷できる。実在するスタッフの初期データは入れていない。
3. 1〜5点または「対象外」を選ぶ。未経験・担当外は対象外とし、未回答に戻す操作も用意する。
4. 成長したこと・強み、改善点、次回評価までの行動目標を記入する。
5. 「評価結果をコピー」、または「印刷・PDF保存」で現在の部門の結果を手元に残す。コピーが拒否された場合は、手動選択できるテキスト欄を表示する。印刷では選択した回答・氏名等・振り返りを文字で出力する。

部門切替では、それぞれの回答・振り返りを独立して保持する。ページ移動・再読み込みで失われることを画面内に明記する。

## 計算

- 1点：継続的な指導が必要。
- 2点：一部で指導や支援が必要。
- 3点：通常業務を自立して遂行できる。
- 4点：指示がなくても安定して実践できる。
- 5点：他者に指導でき、安定して実践している。

100点換算は `採点した項目の合計 ÷（採点した項目数 × 5）× 100`。対象外・未回答を分母へ含めない。回答数は「採点＋対象外」とし、採点・対象外・未回答の内訳を分けて示す。

未回答が残る間は暫定点とし、S〜Dの区分を確定しない。全項目対象外でも回答は20件になるが、点数・区分は未採点とする。表示は小数第1位まで、区分判定は丸め前の値を使う。

全項目の回答が揃い、採点項目が1件以上あるとき、90点以上S、80点以上A、70点以上B、60点以上C、それ未満Dを「自己評価の区分目安」として表示する。

## 人事制度との関係

39期の運用案として、1月の自己評価・上司評価・育成面談、4月の昇給・昇格の実施検討、7月の半期評価・育成面談・次期目標設定を掲載する。昇給査定は原則年1回とする案。

区分別の対応は制度上の検討目安。自己評価だけで給与を決めず、本人の自己評価と上司評価を比較し、面談を経て最終評価を決定する。昇格・昇給を保証しない。部門ごとの仕事の難易度が異なるため、同じ点数を部門横断の能力比較として扱わない。

## 保存・プライバシー

現段階は認証前の入力フォーム。個人の評価記録をサーバーへ送信せず、ブラウザーのLocalStorage・SessionStorage・URLにも保存しない。Reactの画面内状態でだけ保持する。既存のポータル・財務の保存領域へ評価を混在させない。部門リーダーを選んでもシステム権限や所属店舗は変更しない。

コピーと印刷は本人が明示的に実行する。クリップボードやPDF等に出した内容の保存先・共有範囲は本人が確認する。本人確認・本人と許可された管理者だけが閲覧できる評価台帳、上司評価入力、面談記録の共有、昇給の確定処理は未実装。

継続的な保存・管理者との共有は、個人ログインとサーバー側の権限、非公開DB、監査履歴を導入してから実装する。サンプルの権限切替を個人認証として扱わない。
