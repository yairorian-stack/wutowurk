# WUTO-WURK Growth Portal

ウトウークスタッフ成長支援ポータルの操作できる試作品です。

**氏名・メール確認コード・管理者承認によるログインを実装しました。Supabase・メール送信元・Next.js公開サーバーは未接続で、本番ログインはまだ利用できません。現在のGitHub Pagesはログイン準備画面だけを公開し、社内画面を開けません。接続手順は [docs/AUTH_SETUP.md](docs/AUTH_SETUP.md)。業務データの共有DB化は引き続き未実装です。**

## 起動

Node.js 24.19.0（`.node-version`）、npm を使用します。Node.js 22.12 以上に対応。

```sh
cd /workspace/wutowurk
npm ci
npm run dev
```

ポートは3000です。本番用のビルドとローカル起動は `npm run build` → `npm run start`。外部サービス・APIキー・DBは不要です。環境のホームディレクトリに書き込めない場合は `npm_config_cache=/tmp/wutowurk-npm-cache npm ci` を使えます。

## 試せること

以下は認証接続・管理者承認後のNext.jsアプリ、または内部の架空プロトタイプで利用する機能です。公開中のGitHub Pagesからは社内画面へ進めません。

「売上・日報」は、接続されていない場合に「ポータル未反映」と表示します。元のスプレッドシートが未集計という意味ではありません。提供された月累計は基準日・出典を付けて先行表示できますが、実額の公開には別途承認が必要です。操作を試すには「サンプルで操作を試す」を選んでください。既存の確認用記録は維持し、CSVも「確認用」の区分を付けます。

- ホーム：今週の店舗目標、完了率、理念・ビジョン、お知らせ。スマートフォンでは週次目標が先に表示されます。
- ビジョン：2026〜2046年の7期間を選択し、状態・目標・行動・指標・移行条件を確認。全社・システム管理者プレビューで編集できます。
- 週次目標：2店舗切替・全社表示、週選択、登録・編集、4種類の達成状況、成果・振り返り・次週の課題、変更履歴。過去の記録検索、担当・状況・期限による絞り込み。
- 複製・繰り越し：先週から複製、未完了を翌週へ。元の記録を保持し、期限を新週へ移動します。同じ移行の二重実行を防ぎます。
- 資料：HTML形式の使い方サンプルを検索・閲覧。原本PDF・就業規則・休暇規程はまだ掲載していません。
- 設定：4権限と所属店のデモ切替。実在人物のアカウントはありません。
- 売上・日報：本店・羽ノ浦店の売上、1日の振り返り、全員の総労働時間を記録。月次の前年同期間比較、累計グラフ、入力不足の表示。
- 日報1回で反映：日報にその日の現金入出金もまとめて入力し、1回の保存で出納帳・月間売上・総労働時間・人時売上高へ反映。入力不備・保存エラー時は部分保存しません。
- 月次目標：店舗ごとに売上目標と人時売上高目標を設定。前月コピー、達成率・残り売上・労働時間の目安、全社集計、変更履歴を確認できます。
- 自己評価：ホーム・売上日報の「自己評価シートを作成」から調理・接客・部門リーダーの3種類を入力。20項目の100点換算、対象外・未回答・暫定点、振り返り・次の目標、結果コピー、印刷・PDF保存に対応します。個人の回答は送信・自動保存せず、ページ移動で消えます。詳細は [docs/SELF_EVALUATION.md](docs/SELF_EVALUATION.md)。
- シフト：店舗別の月間カレンダー、日別の勤務時間帯、人数、休憩を除く予定労働時間。共通CSVを画面内だけで読み込み、保存・送信しません。Airシフトは外部リンクのみで、自動取得は未接続です。
- 本店の紙シフトは直接入力・CSVでの控え保存に対応します。ゴミ出しはホーム・日報の「本店ゴミ出し」から18番地区の提供日程と通知予定を確認できます。自動通知は未稼働です。[GAS実装・Google設定手順](automation/garbage/README.md)を用意しています。
- 提供売上：サンプルと別にJSONの全日別累計を検証して表示。「この端末に保存」で専用キーへ記録し、バックアップできます。共有DBへの登録や実売上の一般公開ではありません。詳細は [docs/SHIFTS_AND_IMPORTED_SALES.md](docs/SHIFTS_AND_IMPORTED_SALES.md)。
- 現金出納帳：現金売上の自動反映、仕入れ・寄付・支払い・名称を記入できる自由項目、レシート金額・摘要、割引券の使用枚数・割引額、開始残高、月初繰越、現金照合、訂正・理由付き取消・履歴、CSV出力。詳細は [docs/FINANCE.md](docs/FINANCE.md)。実データ向けではありません。

最初は架空の「全社管理者」プレビューです。ホームの本店は3件中1件が完了（33%）。目標の新規登録は、週次アクションで次週を選ぶか、2件登録済みの816を選ぶと試せます。目標は1店舗・1週間で最大3件です。

## 保存と制限

ローカルストレージ `wuto-wurk-prototype-v1` にサンプルを保存します。再読み込み後も残りますが、端末間の共有・アカウント分離・バックアップはありません。ブラウザーデータの削除で初期化されます。保存容量不足時はエラーを表示し、保存済みと表示しません。同一ブラウザーの複数タブは保存通知で追従しますが、同時更新の競合解決は本番のサーバー保存で実装します。

自己評価の氏名・回答・振り返りは上記の保存対象に含めません。画面内だけで保持し、コピー・印刷以外の自動保存・送信は行いません。

通常ログイン後は、端末内記録のキーをユーザーIDで分離し、ブラウザー内の役割選択を認証やシステム権限に使いません。旧共通キーの記録は消さず、自動で新アカウントへ移行しません。認証・登録承認・権限のDB検証と、業務データの共有保存は別の実装段階です。

UIプレビューでは役割に応じて店舗・編集操作・資料の表示を変えていますが、全サンプルデータはブラウザー内に存在し、開発者ツールで閲覧・変更可能です。これは本番セキュリティの検証ではありません。

PWA用マニフェストとアイコン、モバイル表示を用意しています。インストール可否はブラウザー・HTTPS条件に依存します。サービスワーカー・オフライン編集・プッシュ通知は未実装で、機密資料をキャッシュしません。

サンプルの週は初回表示時点の日本時間で生成します。日付計算は `Asia/Tokyo` を基準とし、週は月曜〜日曜。ビジョンの行動・指標・移行条件、価値の説明文は検討用の表現案です。

## 検証

GitHub Pages用の自己完結型サンプルは `npm run build:pages` で `out-pages/` に出力します。店舗ID `816` は羽ノ浦店を指し、表示名変更後も既存の目標・記録を維持します。財務サンプルは別キーに保存し、従来のポータル保存データを初期化しません。

```sh
npm run lint
npm run typecheck
npm test
npm run build
npm run test:e2e
npm run test:auth
```

E2E はデスクトップと iPhone サイズの Chromium で実行します。`/usr/bin/chromium` を既定としています。他の環境では `CHROMIUM_PATH` に利用可能な Chromium のパスを指定してください。`test:e2e` は本番サーバーを自動起動します（先に `build` が必要）。既存サーバーがある場合はそれを使います。スクリーンショットと失敗時トレースは無視対象の `test-results/` に出力します。

詳細設計は [docs/DESIGN.md](docs/DESIGN.md)、本番化前の確認事項と手順は [docs/OPERATIONS.md](docs/OPERATIONS.md) を参照してください。
