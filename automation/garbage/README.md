# WUTO-WURK 本店ゴミ出し通知（Google Apps Script追加実装案）

対象は18番地区（福井・後戸・鵠）。既存の「ウトウークゴミ出しPJ」に追加するコードです。**現時点では未設置・未稼働です。実PDFの構造、Google権限、メール・LINEへの実着信は未検証です。**

## ファイルと現状

- `Core.gs`：公式ページのPDFリンク探索、本文年月の検証、18番地区の表解析、前日17時・19時、日越通知文。外部サービスへの送信処理なし。
- `Runtime.gs`：公式PDF取得、DriveでのOCR・表読取、検証済み形式のキャッシュ、メール・LINE送信、重複防止、監査記録、管理者警告、専用トリガー。
- `TestNotifications.gs`：手動の接続テスト。定期処理は呼びません。既存のLINEテスト関数を変更・削除しません。
- `appsscript.example.json`：追加権限の例。既存マニフェストへ必要項目を**併合**し、既存のスコープ・サービスを削除しないでください。
- `tests/unit/garbage.test.ts`：11月の依頼者提供日程との照合、年月・曜日・表変更、JST・境界時刻、送信重複・失敗を外部サービスのモックで検証。

2026-10-25の環境では公式ページへのCONNECTが403で拒否され、PDF本体を取得できていません。解析器は、**地区番号・地区名の列と品目別の日付列を持つ構造化表**を前提とした初期アダプターです。実PDFやOCR後の表に適合することは未確認です。OCRが表を保持しない、行が縦横に組み替わる、地区名を誤認する等の場合は停止します。実資料を確認してアダプターを調整する工程が残っています。合成の表を実PDFの証拠として扱いません。

## Google側での設置手順

1. Apps Scriptで既存の「ウトウークゴミ出しPJ」を開き、既存コード・マニフェスト・トリガー構成を控えます。秘密値はチャットやGitへ貼らず、プロジェクト内のスクリプトプロパティに保持します。
2. 既存のLINEテスト通知を先に実行し、今までどおり動くことを確認します。既存関数やプロパティ名は変更しません。同じ定期通知を既存処理でも送っている場合は、二重運転を避けるため管理者が旧トリガーを特定してから切り替えます。このコードは既存トリガーを削除しません。
3. `Core.gs` と `Runtime.gs` を新しいスクリプトファイルとして追加します。接続テストを行う場合は `TestNotifications.gs` も追加します。
4. プロジェクトのタイムゾーンを `Asia/Tokyo`、ランタイムをV8にします。「サービス」からDrive API v3を**識別子 `WWGDrive`** で有効にします。関連Google CloudプロジェクトでDrive APIの有効化を求められた場合は有効化します。既存Driveサービスを勝手に置き換えないでください。
5. 管理者だけが閲覧できる管理用スプレッドシートを用意し、IDを下記プロパティへ設定します。監査シートは初回に作成されます。宛先や監査内容をWeb公開しません。
6. 下記のプロパティを追加します。`WWG_ENABLED` は `false` のままにします。LINEの既存値を複製せず、その**プロパティ名**を指定します。
7. `wwGarbageRefresh` を手動実行し、Googleの権限要求を確認して承認します。必要な権限は、公式サイト・LINEへの外部通信、メール送信、トリガー管理、作成したDriveファイルの変換・整理、Googleドキュメント読取、管理シートへの書込です。`MailApp` を使い、受信メールは読みません。OCRで作成した一時ドキュメントはゴミ箱へ移します。
8. 管理シートの `extraction` 行と、スクリプトプロパティ `WWG_REVIEW_YYYY-MM` を確認し、公式PDFの本文年月・18番地区の全6種類・日付・曜日を目視照合します。形式が違う場合は解析器を直して再検証します。PDFファイル名だけで月を決めません。
9. `WWG_REVIEW_MONTH` に確認月、`WWG_REVIEW_CONFIRM` に `公式PDFと18番地区の全日付を目視照合済み` を設定し、`wwGarbageApproveLayout` を実行します。これは指定形式の承認で、定期配信の有効化ではありません。もう一度 `wwGarbageRefresh` を実行し、`WWG_SOURCE_HEALTH=ready` を確認します。
10. `wwGarbageDryRun` を実行し、日本語・ベトナム語、朝8時、公式リンク、前日17/19時を管理シートで確認します。**送信はしません。** 分別説明は一般的な案なので、公式ルールと照合し、ベトナム語も運用担当者に確認します。
11. 接続試験は `WWG_ENABLED=false` の状態で `WWG_TEST_CONFIRM=設定済み通知先へテスト送信` を設定して `wwGarbageTestSend` を手動実行します。これは設定済みの3メールとLINEグループへ、テストと明記した通知を実際に送ります。全員の受信と既存LINEテストが維持されていることを確認します。確認用プロパティは実行前に削除されます。
12. 日程・送信先・通知精度が確認できたら `WWG_ENABLED=true` にし、`wwGarbageInstallTriggers` を実行します。毎分の通知判定と6時間ごとのPDF再取得を作成し、既存トリガーは維持します。通常の「実行」権限とインストール型トリガーを使うため、**Webアプリとして一般公開するデプロイは不要**です。

## スクリプトプロパティ

| キー | 内容 |
| --- | --- |
| `WWG_ENABLED` | 初期は `false`。検証後だけ `true` |
| `WWG_ADMIN_EMAIL` | 取得・解析・送信エラーの警告先 |
| `WWG_EMAILS_JA` | 日本語宛先のJSON配列。例：`["owner@example.com"]` |
| `WWG_EMAILS_VI` | ベトナム語宛先のJSON配列。例：`["staff1@example.com","staff2@example.com"]` |
| `WWG_LINE_TOKEN_PROPERTY` | 既存LINEアクセストークンを保存しているプロパティ名 |
| `WWG_LINE_GROUP_PROPERTY` | 既存の本店LINEグループIDを保存しているプロパティ名 |
| `WWG_AUDIT_SHEET_ID` | 非公開の管理用スプレッドシートID |
| `WWG_REVIEW_MONTH` | 目視照合する `YYYY-MM` |

依頼者指定のメールアドレスは公開リポジトリ・ポータルへ記載していません。警告先は日本語の通知先と同じアドレスを初期案とし、実設定時に確認してください。LINEのトークン・グループIDの実値は未受領です。LINE Botが既存グループで利用でき、Messaging APIのプッシュ送信が契約・上限の範囲内で使えることを確認します。有料契約は行いません。

## 正確性・時刻・重複・失敗

公式ページの現在のPDFリンクを毎回探索します。同じ公式ホストのPDFだけを取得し、PDF本文の年月を検証します。日付の空欄、存在しない日、曜日不一致、地区18の欠落・重複、表の列変更、同月PDF間の矛盾は収集通知を停止します。古紙は抽出しません。承認済みの列構造と一致した当月・翌月だけを運用キャッシュへ入れます。キャッシュの鮮度は30時間以内とし、取得に失敗したら古い結果で配信を続けません。1回の取得処理は最大20リンク・240秒を上限とし、全件を安全に確認できなければ停止します。通知枠付近は長時間の取得処理を開始しません。

毎分のトリガーで日本時間17:00と19:00の枠を判定し、**0〜299秒の遅延を許容する初期設定**です。GASの時間トリガー・メール・LINEには遅延があり、17:00:00/19:00:00ちょうどの着信は保証できません。5分を過ぎた枠は後追い送信せず、管理者へ警告します。この許容幅は実運用前に依頼者と確認し、厳密な時刻保証が必要なら別のスケジューラーを検討します。新規の有料サービスは自動契約しません。

管理シートは予定時刻との差 `late_seconds` を送信開始・API完了時に記録します。`SENT` は送信APIの成功応答で、実着信確認とは別です。少なくとも複数の通知日・両時刻で、GAS実行履歴・宛先メール・LINEの実時刻を突き合わせ、許容幅内か確認する必要があります。実環境の配信精度はまだ測定していません。

同日複数品目は1通にまとめ、宛先ごとに `収集日 + 17/19時 + 宛先ハッシュ` の記録を保持します。ScriptLockで並列実行を防ぎ、送信前に `CLAIMED` を保存します。送信直後のタイムアウト等は「届いたか不明」なので自動再送しません。`UNKNOWN` または残った `CLAIMED` は管理者が受信結果を確認します。**完全なexactly-once着信は保証できず、重複防止を優先して未送信を管理者へ回す設計**です。手動で記録を消して再送する前には、必ず届いていないことを確認してください。

警告は同じエラー種別で1日1回に抑え、ログにトークン・グループID・宛先メールの実値を出しません。メール自体の障害では管理者メールも届かないため、Googleの実行失敗通知と管理シートも確認します。処理済みキーは90日、監査シートの履歴は保持します。

## 検証範囲と残作業

11月の依頼者提供日程はプラ6/17、カン13、PET24、ビン25、不燃/粗大27で照合します。前日の11/5・12・16・23・24・26、それぞれ17時と19時の計12枠になります。10月の実収集日はこの会話では未提供のため、10月の公式日程との照合は未実施です。10月1日の月またぎ等は合成データの境界テストであり、10月の実予定ではありません。

残作業：既存GASコードとプロパティ名の確認、公式10/11月PDF取得、実OCR構造への適合・全日付照合、Google権限承認、通知先設定、実受信試験、時刻精度測定、定期稼働。既存LINEテストを保持できることも実プロジェクトでの確認が必要です。ポータルは未稼働・照合用と明示し、管理用シートを公開しません。

停止するときは `wwGarbageStop` を実行します。既存プロジェクトや既存LINEテストは削除されません。
