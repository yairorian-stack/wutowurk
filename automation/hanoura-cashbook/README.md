# 816 現金出納帳入力アプリ

スマートフォン/タブレット用Google Apps Script Webアプリです。Google Sheets/Drive/MailAppの通常枠を使い、追加の有料ホストを必要としません。正式な元帳へのテスト行・実メール送信・公開デプロイは、開発環境からは実行していません。

## 現在確認できた原本

2026-11-25に既存ファイルの読み取りを行い、正本「39期目816　出納帳」、11月AM:AT、11/24最終明細行94と以後の入力用空き行、既存数式を確認しました。2026-11-27の再確認では11/25分までの追記を確認しました。初回有効化では、その時点の最終登録日の翌日を明示し、管理者が残高と開始日を承認します。既に手入力された11/25などを重ねて登録しません。原本は変更していません。金額や原本ID/利用メールはこの公開リポジトリに記録しません。日付・行番号は取得時点の観測で、初回設定時にライブデータから再検査し、変わっていれば停止します。

原本を未認証でも取得できたため、運用前に一般アクセスを「制限付き」へ変更する必要があります。既存の個別共有（スタッフ、税理士、取込専用アカウント等）は削除しません。アプリは一般公開された元帳/写真フォルダへの保存・読取を拒否します。

## 実装済み

- 許可リストの本人に届く6桁コード。10分、誤試行5回、送信は1分間隔/宛先毎時5回/全体制限。本人確認後のセッションは最大6時間（Cache早期失効時は再ログイン）。許可取り消しは各リクエストで確認。未知アドレスにも同じ応答。
- 営業日・担当、総売上、カード、PayPay、3種の金券、現金売上の計算。金券販売と利用は別集計。空欄0円、実査現金未入力はnull。
- 複数仕入れ・業者候補と自由入力・支払方法・写真。現金以外は残高から控除しない。写真は端末で圧縮し、Driveの非公開フォルダへ保存。
- 前回残高の繰越、帳簿残高・現金過不足、確認→保存。別のログイン実行者と担当者名を区別して監査。
- 日報は営業日1件、版番号で競合検知、同じ送信番号の再送は冪等。LockServiceで同時登録を直列化。
- 原本の当月のアプリ専用空き行へ、従来どおり総売上入金＋決済控除・現金仕入れ・入出金・銀行預入を記録。購入画像のリンクは該当行の概要へ設定。リンク先もアプリの本人確認必須。
- 保存原本・元帳・購入/入出金明細・監査履歴をSheets APIの単一batchUpdateで記録。途中失敗で別々の部分保存にしない。応答を失った場合は記録を再読取し、保存済みなら成功、未確認なら再送を促す。
- 従来の過去行・数式は保持。開始前の明細/残高、登録済み行、空き行に別データがある場合は停止。保存用補助シートと当月アプリ入力範囲を保護し、アプリ経由の修正へ誘導。
- 下書きは端末のIndexedDBへ保存し、写真も復元。サーバー確認済みの保存時だけ消去。未送信の下書きは他端末へ共有しない。

## 公開手順（所有者）

1. **元帳を制限付きにする。** 元帳の「共有」→「一般的なアクセス」→「制限付き」。既存個別共有は残す。元帳のコピー/バックアップを所有者が非公開で確保する。
2. [新規Apps Scriptプロジェクト](https://script.google.com/home/start)を開く。**既存のスクリプトへ上書きしない。** 所有者向けに別途用意した1ファイルのコードをCode.gsへ貼り付ける。公開リポジトリ版を使う場合はCore.gs、Server.gs、Index.htmlを同名で追加するか、`node scripts/build-hanoura-cashbook.mjs`で結合する。接続ID・許可者はScript Propertiesへ設定する。
3. 左の「サービス」＋から **Google Sheets API（v4、識別子Sheets）** を追加。標準のGoogle Cloudプロジェクトを別途使用している場合だけ、同プロジェクトのSheets APIも有効にする。カード登録・有料契約は不要。マニフェスト例はappsscript.json。
4. 関数選択で **ownerSetup_**（所有者向けファイル）を選び実行し、自分の新規プロジェクトだと確認してGoogleの権限を承認。Spreadsheet/Drive/メール送信を使う。これは元帳への入力は行わず、同じファイルに4つの専用タブと非公開の写真フォルダを作る。許可メールを一斉送信しない。
5. 「デプロイ」→「新しいデプロイ」→歯車→「ウェブアプリ」。実行ユーザーは**自分**。アクセスは**Googleアカウントを持つ全員**を選ぶ。Googleのアクセス制限に加え、アプリ側で登録メールの確認コードが必須。Googleアカウントのログインだけで元帳は表示しない。
6. デプロイ後の **/execで終わるウェブアプリURL** を控える。/devはスタッフへ渡さない。所有者のメールでログインし、元帳から取得した最終登録日の残高とアプリ入力開始日を確認して「この残高を確認して入力を有効にする」を押す。先月繰越から推測せず、既存最終行の残高を明示的に承認する。
7. 所有者が当日の**本物の入力**を1件保存し、元帳・登録日時・担当・現金残高・写真リンクを確認。テストしたい場合は、元帳をコピーした専用テストファイルと別プロジェクトを使う。正式元帳へ架空行を登録しない。
8. 所有者が/exec URLをスタッフへ共有する。開発者からLINE送信は行わない。GoogleのMailAppによる認証メール着信・Google API/Drive保存・モバイル実機の最終検証は、この公開操作後に必要。

### 設定項目（すべてScript Properties、実値は公開しない）

| 名前 | 内容 |
|---|---|
| CASHBOOK_SPREADSHEET_ID | 既存の保存先ファイルID |
| CASHBOOK_SOURCE_GID | 正本タブの数値ID |
| CASHBOOK_USERS | 正規化したメールをキーに{name,role:adminまたはentry,enabled:true}を持つJSON |
| CASHBOOK_START_DATE | 運用開始日 YYYY-MM-DD |
| CASHBOOK_RECEIPT_FOLDER | 初回設定が自動作成する非公開フォルダID |
| CASHBOOK_PLAN | 管理者が前回残高を確認した時に保存する接続状態。手で変更しない |

利用アカウントの追加/停止はCASHBOOK_USERSを所有者だけが変更する。編集用Apps Scriptプロジェクトは担当者へ共有しない（WebアプリURLのみ共有）。OTPはGAS MailAppの通常上限に依存し、利用可能枠を超えた場合はログインができないので少人数で確認する。

## 店長・担当者の操作

1. /exec URLを開き、登録メール→メールに届いた6桁コードでログイン。
2. 営業日を確認。担当者はログインした人を初期表示し、代理入力時は変更できる。保存アカウントは変更できない。
3. 総売上・決済/金券・購入を入力。銀行預入は現金出金、金券販売は現金入金、金券利用は売上の非現金控除。
4. 現金を実際に数え、残高を入力。「入力内容を確認する」→「この内容を登録する」。**登録が完了しました**が表示されたら終了。
5. 間違いは同じ日付を選び、登録内容を読み込んで修正する。画面に古い版が残っていたら再読込し、他の人の変更を確認する。
6. 通信エラーは内容を変えず再送。元帳が手修正された警告は強引に続けず所有者へ連絡。写真はDriveに一般公開しない。

## 経営者の確認と限界

- 元の正本タブで現金の動きを確認。816入力_日報は保存原本、816入力_購入明細/入出金は集計用、816入力_変更履歴は監査用。これらの値や式を手修正しない。
- 日報を過去日へ修正した場合、それ以降のアプリ登録分の計算残高も再計算。過去の実査現金の値そのものは変更せず、過不足を再計算する。
- 新しい月は原本の年/月/8列見出しから一意に確認できる既存空きブロックへ記録する。対象月が未確認/複数/入力済み/行不足なら停止。新しい月・年を推測して既存欄を上書きしない。月欄の新規追加は管理者対応。
- Apps Script/Sheets API/Drive権限・Google利用枠・公開URLは実運用で要確認。この環境には認証済みGoogle編集接続がないため、公開と本番書込はまだ行っていない。
- 画像圧縮はブラウザー依存。古い端末などでIndexedDBが使えない場合は画面内保持のみとなり、再読込では失われることを表示する。端末外の自動バックアップではない。
- 写真作成後に保存前エラーが起きた場合、参照されない非公開写真が残ることがある。応答不明で正式保存された画像を誤削除しないため自動削除しない。
- この専用アプリと既存スタッフポータルの店長日報は別の入力元。**同じ日を両方へ二重入力しない。** 既存ポータルへの11月出納帳同期/レシートAI/承認/未入力通知は今回の公開には含めない。

## Macの自動設定（コード貼付を省く方法）

`mac-setup/816自動設定.command` は、Mac専用フォルダに公式Node.js 24（HTTPSとSHA256照合）および固定版のGoogle公式clasp 3.4.1を準備します。管理者パスワード、グローバルインストール、チャットへの認証コード送付は不要です。Googleへのログインと権限承認は所有者が行います。

配布物は `node scripts/build-cashbook-mac-setup.mjs private-config.json private-output-directory` で生成します。private configの項目は `spreadsheetId`, `sourceGid`, `startDate`, `ownerEmail`, `users`（メールをキー、値はname/role/enabled）。実設定と配布ZIPはGit外の非公開領域に置きます。架空設定だけをテストで使用します。

初回GETは設定のみ登録し、シートや共有を変更しません。許可メールのOTPで管理者本人を確認した後、一般公開を解除（個別共有は維持）し、保存用タブ・非公開写真フォルダを作成します。残高と運用開始日の承認はサイトで別途行います。Googleの初回実行承認がWeb側で進まない場合のみエディタから `ownerSetup_` を実行します。既存記入済み営業日を上書きしません。

claspの管理権限はscript.projects/script.deployments/script.webapp.deploy/drive.file/userinfoに限定。Google APIで確認したWEB_APPのURLだけを発行し、ローカル認証情報と状態を所有者のLibrary/Application Support/WUTO-WURK-Cashbookに保存します。作成結果が不明な通信失敗では再作成を止め、既存プロジェクトIDが一致しなければpushしません。初回承認・実メール・本番保存は所有者の認証後の確認が必要です。詳細は `mac-setup/使い方.md`。
